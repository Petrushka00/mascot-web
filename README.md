# MASCOT — Multi-Agent System for Corporate Orchestration of Talent

Интерфейс мультиагентной системы по оценке сотрудников и формированию команд. Проект разработан на платформе **Angular** с фиксированной темной раскладкой для настольных компьютеров (PC).

## Выполнено за 25-28 октября 2026


#### 1. Страницы приложения

Помимо главной страницы в `App` подключены три экрана: `EmployeesComponent` (сотрудники), `TeamsComponent` (команды) и `EvaluateComponent` (оценки). Они импортированы в `app.ts` и отображаются через `@switch` в `app.html`, поэтому требование о нескольких страницах помимо главной выполнено.

`ProjectsComponent` и `CreateProjectComponent` пока неготовы, это просто заготовки.

#### 2. Навигация и переключение страниц

Переключение работает следующим образом: sidebar вызывает `selectPage(...)` по событию `(click)`, отправляет выбранный ключ через `pageChanged`, а `App.navigateTo($event)` записывает его в сигнал `currentPage`. `app.html` выбирает нужную страницу с помощью `@switch` и `@case`.

Кнопки навигации находятся в отдельном `SidebarComponent`, а не внутри Header и не непосредственно под ним. Если задание требует именно такого размещения, этот визуальный пункт еще не выполнен буквально.

#### 3. Event Binding, Class Binding и Property Binding

В кнопках sidebar применены привязки:

- `(click)` вызывает обработчик выбора страницы;
- `[class.active]` добавляет класс активному разделу;
- `[disabled]` отключает кнопку уже выбранной страницы;
- `[activePage]` передает sidebar текущую страницу из родительского компонента.

Таким образом, активное состояние выделяется через Class Binding, а Property Binding используется для состояния `disabled`.

#### 4. Массив, `@for`, `track` и `@empty`

Массивы объектов используются на страницах сотрудников и оценок. Их шаблоны обходят записи через `@for`, используют уникальный и стабильный `id` для `track` и показывают пустое состояние через `@empty`.


В `evaluate.component.html` аналогично используется `@for (evaluation of evaluations; track evaluation.id)`; при пустом массиве выводится сообщение «Нет данных об оценках».

#### 5. Ссылка `#variable`

Ссылки на элементы шаблона используются в `teams.component.html`: `#searchKeyEmployees` и `#searchKey`. Их значения читаются в условиях `@if` и выводятся интерполяцией.

# Выполнено за 08.11.2026 

## 1. Блок отображения сотрудников

Реализован блок отображения сотрудников в виде компактных горизонтальных карточек.

Каждая карточка содержит основную информацию о сотруднике, его статус и оценку. Дополнительная информация и действия располагаются в отдельной нижней строке.

## 2. Структура блока

Блок состоит из двух основных компонентов:

- **EmployeesComponent** — родительский компонент. Хранит список сотрудников и управляет их данными.
- **EmployeeCardComponent** — дочерний компонент. Отвечает за отображение информации об одном сотруднике и передачу события архивации.

## 3. Модель данных Employee

Для хранения информации о сотрудниках используется интерфейс `Employee`.

```ts
export interface Employee {
  id: number;
  name: string;
  position: string;
  department: string;
  evaluation: number;
  status: 'active' | 'archived';
}
```

## 4. Хранение данных

В родительском компоненте `EmployeesComponent` список сотрудников хранится с помощью Angular Signals.

```
employees = signal<Employee[]>([
  {
    ...
  }
]);
```

Использование `signal` позволяет реактивно обновлять интерфейс при изменении списка сотрудников.

## 5. Передача данных в карточку

Для отображения каждого сотрудника используется отдельный компонент `EmployeeCardComponent`.

Данные передаются из родительского компонента через `input.required`.

```
employee = input.required<Employee>();
```

Это позволяет дочернему компоненту получать объект сотрудника и использовать его поля в HTML-шаблоне.

## 6. Архивация сотрудников

Для реализации архивации используется механизм передачи событий из дочернего компонента в родительский.

В `EmployeeCardComponent` создаётся выходное событие:

```
archive = output<number>();

archiveEmployee() {
  this.archive.emit(this.employee().id);
}
```

При нажатии на кнопку «Архивировать» дочерний компонент передаёт ID сотрудника родительскому компоненту.

В `EmployeesComponent` реализована функция изменения статуса:

```
archiveEmployee(id: number) {
  this.employees.update(list =>
    list.map(employee =>
      employee.id === id
        ? { ...employee, status: 'archived' }
        : employee
    )
  );
}
```

В данном случае используются:

- `update()` — обновление значения сигнала;
- `map()` — перебор массива сотрудников;
- оператор `...` — создание копии объекта с сохранением остальных свойств;
- условие проверки ID — определение сотрудника, которого необходимо архивировать.

При архивации изменяется только статус выбранного сотрудника. Остальные данные остаются без изменений.

## 7. Передача события в родительский компонент

В HTML-шаблоне родительского компонента дочерняя карточка подключается следующим образом:

```
<div class="employees-grid">
  @for (employee of visibleEmployees(); track employee.id) {
    <app-employee-card
      [employee]="employee"
      (archive)="archiveEmployee($event)"
    />
  } @empty {
    <p>Сотрудники не найдены.</p>
  }
</div>
```

Здесь:

- `@for` — перебирает список сотрудников;
- `track employee.id` — помогает Angular отслеживать элементы по уникальному идентификатору;
- `[employee]="employee"` — передаёт данные сотрудника в карточку;
- `(archive)` — подписывается на событие архивации;
- `$event` — получает ID сотрудника, переданный дочерним компонентом;
- `@empty` — отображает сообщение, если список пуст.

## 8. Использование ng-content

Для возможности передачи дополнительной информации в карточку используется механизм `ng-content`.

```
<ng-content select="[card-extra]"></ng-content>
```

Он позволяет вставлять дополнительное содержимое в заранее определённое место карточки без изменения её основного шаблона.

Это делает компонент более гибким и позволяет использовать его в разных сценариях.

## 9. Организация интерфейса

Карточка сотрудника разделена на две части.

Основная строка содержит:

- ID сотрудника;
- ФИО;
- должность;
- отдел;
- статус;
- оценку.

Нижняя строка содержит:

- дополнительную информацию;
- кнопку «Архивировать»;
- кнопку «Подробнее».

Для расположения информации используется CSS Grid. Это позволяет выровнять данные по столбцам и сохранить одинаковую структуру всех карточек.

Статусы сотрудников визуально различаются:

- активный сотрудник — зелёный индикатор;
- сотрудник в архиве — красный индикатор.

Для карточек используется общая цветовая система проекта MASCOT.


## Команды разработки (Development Guide)

Этот проект был сгенерирован с помощью [Angular CLI](https://github.com/angular/angular-cli). Ниже приведены основные команды для работы:

### Установка зависимостей
Перед первым запуском обязательно установите пакеты с флагом обхода строгих peer-контрактов для стабильной сборки дерева npm:
```bash
npm install --legacy-peer-deps
```

### Запуск сервера (Development server)
Для запуска локального сервера разработки выполните:
```bash
ng serve --open
```
После компиляции приложение автоматически откроется в браузере по адресу: `http://localhost:4200/`. Страница будет автоматически перезагружаться при изменении любых исходных файлов.

### Создание новых компонентов (Code scaffolding)
Чтобы сгенерировать новый компонент, страницу, директиву или сервис, используйте встроенные инструменты генерации:
```bash
ng generate component component-name
```
Для получения полного списка доступных шаблонов генерации запустите `ng generate --help`.

### Сборка проекта (Building)
Чтобы собрать проект для продакшена, выполните:
```bash
ng build
```
Скомпилированные файлы проекта будут сохранены в директории `dist/`. По умолчанию сборка оптимизирует приложение для максимальной производительности и скорости работы.
